# Always-On Rule: Project Charter

NNOO is built tranche by tranche and feature by feature.

Permanent boundaries:

- One Next.js web application.
- One Expo mobile application.
- One Supabase project per environment.
- One shared source of data, contracts, and business rules.
- One active feature at a time.
- No placeholders, fake records, simulated payments, simulated AI success, or inactive production controls.
- No later-tranche work without explicit approval.
- No completion until tests, regression checks, and documentation pass.

Current state lives in `docs/project/PROJECT_STATE.md`. Agreed scope lives in `TRANCHE_PLAN.md` and `FEATURE_LEDGER.md`.

When chat instructions conflict with approved repository rules or scope, stop and ask David Bako which source should be updated.
